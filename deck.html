01
The Problem

Agents are being handed money. Nobody can check them.

Agents already hold wallets, cards and paid API access. Nothing answers what happens when they don't deliver.

The provider eats the loss

An endpoint serving an unknown agent spends compute before settlement clears. If it never pays, there is no recourse.

A score with nothing behind it

Reputation that is free to lose is free to lie. Burn a rating, register a new key, clean slate the same block.

Permission is solved. Consequence isn't.

Wallets cap what an agent can spend. Nothing makes it pay when it breaks a rule anyway.

No compensation path

When an agent rugs a counterparty there is no way to make the injured party whole. The loss is final.

05
Market

Who pays, and why now

Three buyers, one primitive. Each is already handling agents it cannot verify.

API & MCP providers

Agents call paid endpoints over x402 and MCP. Compute is spent before settlement clears, so paying ability is the whole risk.

Agent marketplaces

Marketplaces listing third-party agents must gate the ones touching user funds. A required bond moves liability onto the operator.

Agent frameworks

Frameworks shipping wallet-holding agents need a trust module, not a compliance team. One import gives users a bond to check.

Agent-to-agent commerce

Two agents transacting unsupervised cannot sue each other. Collateral settles in the same block as the breach.

06
Why Now

The rails are funded. The safety layer isn't.

Colosseum's portfolio builds the agent economy's payment layer. None of it makes an unknown agent safe.

Already funded

Laso, Frames, Clawpump, Flovia, Sudont, MCPay and Corbits, all funded for agent rails, cards and payments.

The gap

Every one assumes the counterparty is good for the money. Nothing answers what happens when an agent takes payment and doesn't deliver.

Why Solana

Breach and payout must land in one block to be cheap. Bond, rules, seizure and compensation are one program, no oracle.

Timing

Agent payment volume is the fastest-growing new counterparty class on Solana, and every provider onboarding to it rediscovers this problem from scratch.

07
Open Source

Public code. Permanent trust.

MIT licensed end to end: program, SDK, plugin, dashboard, read API. Fork it, or run your own registry.

Why This Matters

Closed trust layers can be revoked or priced out of reach. Accountability infrastructure must be open to be trusted, everywhere.

What Happens If It Disappears

Builders lose the only open accountability layer on Solana, and fall back on closed alternatives that can be switched off.

Business Model

We charge for the check, and the bond.

Reading a bond is free forever; a trust layer nobody queries is worthless. Revenue comes from the two sides.

  • Take rate on bonded volume. A basis-point fee when collateral is posted and again when it is slashed. Revenue scales with risk, not signups.
  • Verification API. The public badge stays free. Providers needing threshold checks or webhooks pay, like any risk-data API.
  • Marketplace gating. Platforms requiring bonds for listed agents pay per listing. They move liability; we reach every agent they onboard.
  • What we want: mainnet with an audit, and our first ten external operators bonded. Verdicts are admin-gated today by design; decentralising that is the roadmap.
